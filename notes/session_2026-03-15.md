## What we accomplished today

### 1. Fixed the Lenia simulator (was completely broken)
Three bugs found and fixed in `nca/lenia.py`:

- **FFT kernel padding bug** (root cause): `fft2(fftshift(K), s=(H,W))` was wrong —
  negative kernel lags were placed at rows 13-25 instead of rows H-13 to H-1.
  Fix: embed kernel in full H×W grid first, THEN fftshift, THEN fft2.

- **Wrong kernel function**: was using polynomial `(4D(1-D))^4` (kn=0).
  Orbium uses exponential `exp(4 - 4/(4D(1-D)))` (kn=1). Fixed.

- **Wrong growth function**: was using polynomial growth (gn=0).
  Orbium uses Gaussian `exp(-(U-m)^2/(2s^2))*2-1` (gn=1). Fixed.

### 2. Embedded the real Orbium initial condition
Fetched from Bert Chan's `animals.json` (Chakazul/Lenia on GitHub).
`ORBIUM_SEED` is a 20×20 float32 array decoded from RLE format.
`seed_creature()` now places this exact published seed instead of a hand-crafted ring.
Verified: creature lives and moves in both 128×128 and 64×64 grids.

### 3. Fixed dual-training NaN bug
**Root cause**: pool write-back allowed NCA to corrupt control channels (ch14=mu, ch15=sigma).
When sigma drifted toward 0, Lenia target computed `(U-mu)/sigma` → division by zero → NaN cascade.
**Fix**: re-inject CH_PHYSICS, CH_F, CH_K after every pool write-back in `train_lenia.py`.

## Architecture reminder (channel layout)
```
ch 0     = A (GS food / Lenia activation)
ch 1     = B (GS predator)
ch 2-12  = hidden (NCA owns these)
ch 13    = physics bit (0.0=GS, 1.0=Lenia, re-injected every step)
ch 14    = f (GS) or mu (Lenia)
ch 15    = k (GS) or sigma (Lenia)
```
